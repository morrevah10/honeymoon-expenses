# הוצאות ירח דבש

אפליקציית ווב להתקנה בטלפון, למעקב הוצאות יומי בטיול עם המרה אוטומטית לשקלים לפי שער היום.

הנתונים נשמרים ב־Firestore בענן, עם מטמון מקומי שמאפשר עבודה מלאה גם בלי אינטרנט.

---

## שלב 1 — יצירת פרויקט Firebase

1. היכנס ל‑https://console.firebase.google.com ולחץ **Add project**.
2. תן שם, למשל `honeymoon-expenses`. אפשר לכבות Google Analytics.
3. לאחר היצירה, בתפריט הצד: **Build → Authentication → Get started**, בחר **Google** והפעל אותו. בחר כתובת מייל לתמיכה ושמור.
4. בתפריט הצד: **Build → Firestore Database → Create database**. בחר מיקום (למשל `eur3` או `nam5`) והתחל במצב **production mode**.

## שלב 2 — חוקי אבטחה

ב‑Firestore, לשונית **Rules**, החלף את התוכן בזה ולחץ **Publish**:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

המשמעות: רק משתמש מחובר יכול לגשת, ורק לנתונים של עצמו.

## שלב 3 — חיבור הקוד לפרויקט

1. ב‑Firebase: גלגל השיניים ליד **Project Overview → Project settings**.
2. תחת **Your apps** לחץ על אייקון הווב `</>`, תן כינוי ורשום את האפליקציה. אין צורך ב‑Firebase Hosting.
3. העתק את אובייקט `firebaseConfig` שמוצג.
4. פתח את `config.js` והדבק את הערכים במקום ה‑placeholders.
5. אופציונלי: ב‑`ALLOWED_EMAIL` אפשר לרשום את כתובת הג׳ימייל שלך, וכך אף חשבון אחר לא ייכנס.

## שלב 4 — העלאה ל‑GitHub Pages

1. צור ריפו חדש ב‑GitHub, למשל `honeymoon-expenses`.
2. העלה את כל הקבצים לשורש הריפו: `index.html`, `config.js`, `sw.js`, `manifest.json` ותיקיית `icons`.
3. בריפו: **Settings → Pages**. תחת Source בחר **Deploy from a branch**, ענף `main`, תיקייה `/ (root)`. שמור.
4. אחרי דקה‑שתיים תתקבל כתובת בסגנון `https://USERNAME.github.io/honeymoon-expenses/`.

## שלב 5 — אישור הדומיין ב‑Firebase

בלי השלב הזה ההתחברות תיכשל.

ב‑Firebase: **Authentication → Settings → Authorized domains → Add domain**, והוסף את `USERNAME.github.io`.

## שלב 6 — התקנה בטלפון

1. פתח את הכתובת בכרום באנדרואיד.
2. תפריט שלוש הנקודות → **הוספה למסך הבית** (או באנר ההתקנה שיקפוץ).
3. פתח מהאייקון והתחבר עם גוגל. מכאן והלאה זו אפליקציה עצמאית.

## איך זה עובד

**יעדים** — כל יעד הוא טווח תאריכים. רשומה משויכת ליעד לפי התאריך שלה, אוטומטית. אפשר להוסיף, לערוך ולמחוק יעדים בהגדרות. אם תאריכים חופפים, היעד הראשון ברשימה מנצח.

**שערי מטבע** — נמשכים מ‑frankfurter.app לפי תאריך הרשומה. שערים מתפרסמים רק בימי עסקים, ולכן לתאריך שנופל בסוף שבוע יילקח יום העסקים האחרון — התאריך בפועל מוצג ליד השער. הדרהם לא קיים במאגר ולכן נגזר דרך הדולר בשער הקבוע 3.6725.

השער נשמר בתוך הרשומה. עדכון שערים בעתיד לא משנה הוצאות מהעבר.

אם אין חיבור, האפליקציה תשתמש בשער הקרוב ביותר שכבר נשמר ותסמן זאת. תמיד אפשר להזין שער ידנית.

**אשראי** — לכל הוצאה שסומנה כאשראי מתווספת עמלת המרה באחוז שמוגדר בהגדרות, כדי שהסכום בשקלים יתקרב לחיוב האמיתי.

**ארנקים** — ארנק לכל מטבע מזומן, עם היתרה, שער השוק מול השקל ומול מטבע הייחוס. השקל אינו ארנק אלא שורת הסיכום. ארנק האשראי מצטבר במינוס ומרכז את החוב שייפול בדף החשבון.

היתרה מחושבת כך: הפקדות ‎+‎ מה שנכנס בהמרות ‎−‎ מה שיצא בהמרות ‎−‎ הוצאות מזומן באותו מטבע.

**תנועות** — משיכה מכספומט, מזומן מהבית, והחלפת כסף. תנועה אינה הוצאה ואינה נספרת בסך ההוצאות; היא רק מזיזה כסף בין ארנקים. במשיכה מכספומט ארנק האשראי יורד וארנק המזומן עולה. בהחלפת כסף אתה מזין כמה נתת וכמה קיבלת, והאפליקציה מציגה את השער שקיבלת בפועל ואת הפער מול שער השוק.

**עמלת משיכה** — השדה היחיד במשיכה שכן נספר כהוצאה, כי זה כסף שבאמת אבד. מופיע בקטגוריה "עמלות".

**מחיקה** — רשומה שנמחקת עוברת ל"רשומות שנמחקו" בהגדרות וניתנת לשחזור. מחיקה לצמיתות דורשת אישור נפרד.

**גיבוי** — ייצוא CSV לאקסל, וייצוא JSON מלא שניתן לייבא בחזרה.
